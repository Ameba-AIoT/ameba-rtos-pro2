# `project_info.json5` 手动模式（manual mode）使用指南

## 什么是手动模式

`project_info.json5` 中每个 SoC 条目有两种模式：

| 模式 | images 由谁管理 | build_firmware 后会覆盖 images？ |
|---|---|---|
| `auto` | MCP 自动写入 | **会**（每次编译成功后自动更新） |
| `manual` | 用户手工填写 | **不会**（MCP 永不修改此条目） |

手动模式适合以下场景：
- 烧录预编译好的 release bin（不走本地 build）
- 固定指定的 `flash_ntz.nn.bin` 路径，不让编译结果覆盖
- 需要自定义哪些 image 参与烧录

---

## 配置方法

将 `flash_layout_setting_mode` 改为 `"manual"`，并手工填写 `build_dir` 和 `images[]`：

```json5
"RTL8735B": {
  "flash_layout_setting_mode": "manual",
  "build_dir": "D:\\amebapro2_sdk\\project\\realtek_amebapro2_v0_example\\GCC-RELEASE\\build",
  "images": [
    {
      "path": "D:\\amebapro2_sdk\\project\\realtek_amebapro2_v0_example\\GCC-RELEASE\\build\\flash_ntz.nn.bin",
      "start_addr": "0x0"
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `flash_layout_setting_mode` | ✓ | 固定为 `"manual"` |
| `build_dir` | ✓ | 绝对路径，指向 CMake build 目录 |
| `images[].path` | ✓ | `.bin` 文件绝对路径（`flash_ntz.bin` 或 `flash_ntz.nn.bin`） |
| `images[].start_addr` | ✓ | Flash 起始地址，Pro2 通常为 `"0x0"` |
| `images[].end_addr` | – | 结束地址（含）；省略时按文件大小推算，仅用于重叠校验 |
| `images[].optional` | – | `true` 时文件缺失只警告不报错 |

---

## 从 auto 迁移到 manual

1. 找到当前 `project_info.json5` 中 `RTL8735B` 的 `auto` 条目，将 `generated by build` 注释块内的 images 数据复制出来。
2. 将 `flash_layout_setting_mode` 改为 `"manual"`。
3. 删除 `/* === generated by build, do not edit === */` 注释。
4. 按需调整 `images[]` 内容。

此后 `build_firmware` 编译成功也**不会**覆盖此条目，image 路径由你全权掌控。

---

## 注意事项

- **所有 path 必须是绝对路径**，相对路径会被校验拒绝。
- `images[]` 至少填一项，否则报 `MANUAL_IMAGES_EMPTY`。
- Pro2 使用单一镜像文件；Video+NN build 产出 `flash_ntz.nn.bin`，普通 build 产出 `flash_ntz.bin`，注意路径要对应。
- 注释只能用 `/* */`，不要用 `//`（项目规范）。
